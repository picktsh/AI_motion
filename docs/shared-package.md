# `@ai-motion/shared` 独立发包评估

> 结论：**暂不发布**。包体只有 4 个源文件、103 行类型/常量，价值集中在协议常量与任务/素材类型；在没有第二个消费方之前，独立发布只会多一份版本与兼容维护成本。

## 一、现状

- 内容：`constants`（协议版本、接口前缀、服务名）、`errors`（错误码）、`types`（任务、素材、运行配置等共享类型）；纯 ESM + `.d.ts`，无构建步骤。
- 消费方：`apps/server`、`apps/web` 两个仓内包，走 workspace 引用。
- 耦合：类型与后端响应结构强相关，改接口常量就要同步改包；目前没有外部消费者。

## 二、发布需要补齐的门槛

1. 构建与产物：现在直接暴露 `src/*.mjs|.d.ts`，需加 tsup 或 tsc 产出 `dist/`，并写 `exports` 映射。
2. 版本与变更记录：协议常量 `PROTOCOL_VERSION` 与包版本的关系要定义（包 major 跟随协议 major 或独立）。
3. License：仓库目前无 LICENSE，发包前必须先定开源许可（见 `docs/licenses.md`）。
4. 文档：README 说明三组入口（constants/errors/types）与协议版本约定。
5. 稳定性：错误码与类型至少跑过一个版本的兼容验证，避免外部使用者踩反复变更。

## 三、建议路径

1. 现阶段保持 private，继续用 workspace 引用。
2. 等出现第三方兼容工具（例如独立命令行或第三方面板）真正需要时，再按上面五条补齐后发布到 npm，包名沿用 `@ai-motion/shared`。
3. 若只是想让外部 AI 读到类型，直接给 `dist` + `.d.ts` 的 git 包即可，不必上 npm。

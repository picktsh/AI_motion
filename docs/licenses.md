# 模板许可与再分发核对

> 用途：明确哪些模板包/素材可以进演示站、可以随仓库分发，哪些只能本机自用。
> 结论按包内许可文件与包结构判定；无许可声明即视为未授权再分发，不靠推测。

## 一、结论速览

| 对象 | 许可来源 | 可否再分发 | 可否进公开演示站 |
| --- | --- | --- | --- |
| `kinetic-tech@0.2.7-open-beta` | 包内 `licenses/TEMPLATE-LICENSE.txt`，MIT | 可以，需保留版权与许可声明 | 可以，但只用自带示例素材 |
| 个人下载包（pixel 2.6.7 / main 2.6.5-alpha.2 / template-01/03/04） | 包内无许可文件，`motion.json` 未声明 | 不可以，按个人使用处理 | 不可以，连示例截图也先不入站 |
| 本仓库源码 | 仓库根无 LICENSE、`package.json` 无 license 字段 | 未授权 | 不适用 |

## 二、判定依据

- `kinetic-tech` 的 `motion.json` 指向 `licenses/TEMPLATE-LICENSE.txt`，内容为 MIT：允许使用、复制、修改、合并、发布、再许可与销售，条件是保留版权声明与许可文本。
- 其余五个包只带 `assistant/`、`content/`、`core/` 等运行产物，既无 `license` 字段也无许可文件；按“未声明即未授权”处理，仓库与演示站都不放它们的包体、截图与成片。
- 个人包里存在 `personal/motiongit.key.json` 类调用标识，本身就不能公开（导入时的凭据扫描已拦第三方密钥，`personal/` 目录按包自带凭证单独提示）。

## 三、演示站取材规则

1. 只放 `kinetic-tech` 的自带示例截图/演示片段，附 MIT 声明与来源链接。
2. 面板界面截图可放，但须裁掉本机绝对路径、个人 key、项目标题等私有信息。
3. 不放任何个人包的包体、封面、成片；需要展示“作品”形态时，用 kinetic 模板自渲一条测试片。
4. 演示站不连本机后端，不提供下载入口，只做介绍与导流。

## 四、后续动作

- 仓库若要开源，需单独定许可（MIT/Apache-2.0 待定）并补 LICENSE 与 `package.json` license 字段。
- 每次导入新模板，`templates.lock.json` 已记录包哈希与来源；许可核对按本文件规则逐包确认后再决定是否可分发。

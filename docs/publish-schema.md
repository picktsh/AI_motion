# 发布配置与素材库约定

## 一、两类配置解耦

每条作品目录里有两份职责不同的 JSON，互不混用：

- `user.json`：渲染输入物料清单。驱动出片的画面、旁白要点、素材引用、字幕、音乐引用，由模板脚本消费。
- `publish.json`：发布配置。只管对外发布的标题、正文、话题、封面和备注，不参与渲染。

后续改发布文案不应动到 `user.json`；调整分镜、素材、字幕也不应动到 `publish.json`。

## 二、publish.json 字段

```json
{
  "platform": "douyin",
  "title": "发布标题",
  "body": "正文文案，支持换行",
  "hashtags": ["AI剪辑", "效率工具"],
  "covers": {
    "horizontal": "cover-horizontal.png",
    "vertical": "cover-vertical.png"
  },
  "notes": "发布时间、@账号、置顶评论等备注"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| platform | 否 | 目标平台标识，默认按通用结构呈现；当前个人主投抖音，结构对其他平台通用 |
| title | 否 | 发布标题；缺省时控制台回退显示工程标题 |
| body | 否 | 正文文案，多行保留换行 |
| hashtags | 否 | 话题标签数组，展示时自动补 `#`；元素带不带 `#` 前缀均可 |
| covers.horizontal | 否 | 横屏封面文件名，相对作品输入目录；旧文件 `cover.png` 按横屏封面回退识别 |
| covers.vertical | 否 | 竖屏封面文件名，相对作品输入目录 |
| notes | 否 | 发布备注与注意事项 |

字段全部可选；控制台按已配置项展示，并在发布清单里标出标题、正文、话题、横封面、竖封面各自齐备或缺失。

## 三、目录与查找约定

- 二期结构：`studio/videos/<id>/input/publish.json`，与 `user.json` 同目录。
- 旧结构：`studio/videos/input/publish-<id>.json`（同目录多作品，文件名带作品 id 避免冲突）。
- 控制台依次尝试上述两个候选路径，读不到即视为本作品尚未配置，给出范式提示，不生成占位数据。
- 封面、素材文件都放在作品输入目录下，路径按文件名匹配回显。

## 四、背景音乐约定（公私划分，参考模板）

- 公共库：`studio/music/`，跨作品复用，曲目随附 license 说明；后续做独立 BGM 管理页时按此目录扫描。
- 私有：各作品输入目录内的音乐文件，引用关系记在 `user.json` 的 `media.music` 段，license 也写在该段。
- 模板的公私划分按目录来源区分，BGM 沿用同一思路：公共目录可复用，作品目录内为私有。

## 五、当前边界

本轮控制台只做只读回显：展示发布配置、封面预览、齐备性检查、BGM 信息与音频波形。在界面上编辑并保存配置、把公共 BGM 选用或复制到作品，需要后端补写本地文件的接口，待只读版本验收后再开放，不改动现有只读接口。

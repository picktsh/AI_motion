# AI 创作内容规划

## 一、账号定位

1. 一句话方向：8 年前端工程师自学 AI 创作的实战记录，从第一条成片开始，每期讲清一个真实问题。
2. 人设标签：8 年前端、懂脚本和工作流、正在补 AI 视觉与视频方向、不藏坑也不吹效果。
3. 内容基调：只讲自己踩过的、跑通的、还没搞明白的，不做"零基础也能月入过万"那类夸大标题。
4. 差异化：纯小白讲不了工程化，纯技术号又缺真实上手过程，两边都占是本人最大的优势。

## 二、主打栏目（优先做）

### 栏目 1：复盘记录类

紧跟刚发布的第一条成片，把幕后拆出来，承接第一条视频带来的流量。

选题清单：
1. 第一条 AI 成片是怎么做出来的，从写台词到出片全流程。
2. 这条 35 秒视频里，人声、字幕、BGM、人像分别怎么接的。
3. 三版改版都改了什么：第一版纯文字、第二版加人像、第三版换 CG 形象和紧凑节奏。
4. 一条视频的文案怎么定：钩子、经历线、结尾关注语分别怎么写。
5. 封面是怎么设计的：标题字、人物位置、信息层级怎么安排。

每期固定讲清：当时想做什么、用了什么、卡在哪、最后怎么解决的。

### 栏目 5：成长打卡类

记录阶段进度，攒长期关注，让观众跟着一起看进步。

选题清单：
1. 自学 AI 创作到现在，我接触过哪些东西（ComfyUI、工作流、大模型下载、剪映、即梦 AI、LibTv、MotionGit），各自走到哪一步。
2. 我的工具学习顺序和先后逻辑，为什么先学这个再学那个。
3. 一个月/一个阶段的阶段总结：搞懂了什么、还卡在哪、下期补哪块。
4. 前端背景在学 AI 创作时帮上了什么忙，哪些地方反而要从零补。
5. 下一条、下一批视频打算做什么，公开立计划，做完回来交作业。

打卡类内容可以短一些，重在真实进度，不用每期都做满工程复盘。

## 三、备选栏目（有素材再做）

### 栏目 2：踩坑避坑类

1. 第一次用 MotionGit 踩过的坑：人像裁切、字幕对不上嘴、时长窗留白、BGM 授权、封面素材来源。
2. AI 生成视频哪些能省、哪些必须人工盯。
3. 配音音色、语速、字幕词边界对齐里容易出的错。

### 栏目 3：工具与插件类

1. 剪映、即梦、ComfyUI、MotionGit 各自适合干什么，我怎么搭配用。
2. ComfyUI 出角色图的工作流思路，模型和提示词怎么配。
3. 免费配音方案怎么接，音色和语速怎么调。
4. 只用自己实际上手过的工具，没上手的不下结论。

### 栏目 4：工程硬核类（前端主场，后期再展开）

1. 用前端思维写视频脚本：配置驱动、字段和字数上限怎么管。
2. 怎么用脚本批量合成配音、对齐词边界、拼全长音轨。
3. 工作流里哪些参数该固定，哪些每次要调。

## 四、前 6 条发布顺序

1. 第一条复盘：这条成片幕后全流程（接刚发的作品，简介和评论区引流）。
2. 成长打卡：我接触过的 AI 工具和各自进度，先把人设立住。
3. 复盘记录：三版改版分别改了什么，为什么改。
4. 踩坑清单：第一次做视频踩过的坑，信息密度高、完播好做。
5. 成长打卡：这一阶段搞懂了什么、还卡在哪。
6. 工具分工：剪映、即梦、ComfyUI、MotionGit 我分别拿来干什么。

## 附：工具项目系列选题（边做边发）

> 项目工程过程本身作为内容素材，按 roadmap 阶段推进，做完一个里程碑挑 1–2 条发。栏目编号对应上文主打/备选栏目。

### 阶段 A：起点与破零（打卡 / 复盘）

1. 两周试了 ComfyUI、剪映、即梦、LibTV 和剧本分镜，都停在皮毛，没充值也没成品（栏目 5 打卡）。
2. 靠模板路线做出第一条拿得出手的成片，幕后是怎么跑通的（栏目 1 复盘，承接现有第 1 条）。

### 阶段 B：控制台一期（工程硬核）

3. 8 年前端给自己的 AI 视频工程搭了个本地 Web 控制台（栏目 4）。
4. 只读后端怎么设计：零框架 Node、只绑本机回环、GET 接口、素材白名单回显（栏目 4）。
5. Vue3 + Naive UI + UnoCSS 工作台壳层：明暗主题、侧栏折叠、路由懒加载（栏目 4）。
6. 环境检查页：Node、uv、ffmpeg、Chrome 怎么探测，缺依赖怎么给补装提示（栏目 4）。
7. 后端地址为什么抽到 `.env`，业务代码里不写域名端口（栏目 4 / 栏目 3）。

### 阶段 C：命令台闭环（近期优先，工程硬核）

8. 从只能浏览到能跑命令：本地命令台的白名单、日志回流、长任务轮询怎么设计（栏目 4）。
9. 模板依赖像 node_modules 一样管：锁清单、本地缓存、版本锁定（栏目 4）。

### 阶段 D：.motion 兼容层

10. 自己写模板读取器和校验器：ZIP 边界、路径穿越、重复条目、哈希完整性检查（栏目 4）。
11. JSON Schema 驱动参数表单：模板可改内容怎么可视化呈现（栏目 4）。

### 阶段 E：素材管理与 AI 助手

12. 作品、配音、BGM 在工程里怎么归置，公私素材怎么分（栏目 1 / 栏目 4）。
13. 接大模型写文案和封面：结果怎么落盘，哪些环节必须人工确认（栏目 4 / 栏目 3）。

### 阶段 F：开源准备与对外展示

14. 开源前补了哪些工程规范：目录分层、类型定义、文档、测试夹具（栏目 4）。
15. GitHub Pages 演示站怎么搭，静态展示和本地工作台怎么分工（栏目 4 / 栏目 3）。
16. 可复用内核怎么抽成独立包（栏目 4）。

### 编排备注

1. 每个里程碑完成后挑 1–2 条；过程中留好截图、日志、界面录屏作为素材。
2. 视频只展示公开 demo 素材，不出现本机绝对路径、个人 key、私有成片和字幕稿。
3. 选题和 roadmap 阶段一一对应，做完一条回台账勾一条；README、docs 和演示站文案与视频素材互相复用。
4. 工具对比只讲自己实际上手过的部分，没用过的不下结论。

## 五、单条视频通用结构

1. 开头 3 秒钩子：先给结果或抛痛点，比如"第一条 AI 成片，我返工了三版"。
2. 过程：按时间顺序讲做了什么、卡在哪个点。
3. 工具和参数：用了什么工具、关键设置是什么，能给截图给截图。
4. 坑和结论：哪里别走我的弯路，最后一句话总结。
5. 结尾引导：下期讲什么，或者问观众卡在哪一步。

## 六、创作提醒

1. 电脑配置、跑速这些，用本机实测的数据讲；没测过的先不测不写。
2. 每条涉及 AI 生成的画面，记得带平台 AI 声明；引用别人素材先标来源。
3. 工具横向对比只说自己上手的部分，没用过的不下结论。
4. 文案不写"最快""第一""爆款"这类绝对化说法。

## 七、待确认项

1. 更新频率：推荐每周 1 条，先保质量不断更。
2. 出镜方式：推荐前期用画面配音不出镜，和第一条形式一致；后期再考虑真人露脸。
3. 首要目标：推荐先做作品积累和垂直人设，不急于变现；如果想往接单或教程付费走，选题结构再单独调整。
